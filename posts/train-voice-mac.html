在 Mac 上从零训一个自己的声音

从一段十分钟的干声，到一首能听的翻唱。写给第一次动手的人，也写给下次已经忘了这次怎么跑通的我。

2026-11-03约 15 分钟macOS / Apple Silicon

先说清楚：这套东西能干什么，不能干什么

RVC（Retrieval-based Voice Conversion）做的事情只有一件：保留原音频的内容、语气和节奏，把音色换成你的模型。所以它不能无中生有——想让它唱歌，你得先有一段别人唱好的干声，它只负责换嗓子。

三条判据，命中两条再动手：一是有稳定的语料来源（自己的录音，或者某个角色的语音包），二是要反复出同一批成品（翻唱、配音、口播），三是能接受几小时的空转。只想听个新鲜，找个在线工具更快。

还有一个前提要先接受：模型的上限由语料决定，不由训练轮数决定。拿合成音（TTS）去训，出来的声音一定带一股机械味，再多跑两百轮也救不回来——这条我踩过，后面细说。

硬件与时间预算

阶段M 系列 Mac（实测）说明
切片 + 提特征（10 分钟语料）2～3 分钟CPU 跑，跟训练抢核
训 32k 模型 200 轮约 1 小时最快能听的一档
训 40k 模型 200 轮约 5～6 小时1.5～1.7 分钟/轮，音质更好
换声推理（3 分钟歌）2～3 分钟f0 用 rmvpe 稍慢但准

注意事项：训练时机器会持续吃满 CPU/GPU，风扇基本不停。别在同一台机器上同时跑训练和推理，两边都会变得很慢，而且偶发静默崩溃。

第一步：把环境装好

用独立的 venv，别污染系统 Python。Python 3.10～3.12 都行，这次用的是 3.12。

# 1. 拿代码
git clone https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI.git
cd Retrieval-based-Voice-Conversion-WebUI

# 2. 建虚拟环境（路径随你，记住它）
python3.12 -m venv .venv
source .venv/bin/activate
pip install -U pip

# 3. 装依赖：Apple Silicon 用 CPU/MPS 版 torch
pip install torch torchaudio
pip install -r requirements.txt

# 4. 下载底模（必须，不然训练没有起点）
#    assets/pretrained_v2/ 下需要 f0G40k.pth / f0D40k.pth（40k）
#    f0G32k.pth / f0D32k.pth（32k），以及 assets/hubert_base/
python tools/download_models.py    # 或者按 README 手动放

装完先跑一次 python webui.py，能打开 http://localhost:7865 就说明环境没问题。后面命令行出问题时，回图形界面跑一遍，是判断「环境坏了」还是「命令写错了」最快的办法。

第二步：准备语料（决定成败的一步）

目标是 5～10 分钟干净人声。少了学不像，多了收益递减，而且训练时间线性增加。

  • 自己录：手机自带录音即可，安静房间，离麦 15cm，正常音量，别离太近喷麦。一次录 10～20 秒，说点有情绪的话，别念课文——语气越平，模型越机械。
  • 从视频里扒：yt-dlp -f bestaudio -x --audio-format wav <URL>。优先找标注「语音合集」「纯享版」的，带 BGM 的先用 demucs 分轨：python -m demucs --two-stems=vocals -n htdemucs input.wav，取 vocals.wav。
  • 统一规格：单声道、wav、16bit。采样率交给后面的预处理，不用手动转。

注意事项：不要把不同人的声音混进一个实验（除非你就要多人模型）。同一个人的语料里，情绪越丰富越好——笑、惊讶、撒娇、生气，各留几条，这是「像不像活人」的关键，比多训 100 轮有用得多。

第三步：切片、重采样、提音高

RVC 的训练脚本吃的是切好的 3.5～4 秒小段，外加每段的 f0（音高）和 HuBERT 特征。这几个目录别手动建，让脚本生成。

cd /path/to/Retrieval-based-Voice-Conversion-WebUI

# 参数顺序：语料目录 采样率 进程数 实验目录 是否禁用并行 切片长度
python train/preprocess.py \
  "/path/to/your_dataset" \
  40000 4 "`pwd`/logs/myspeaker" False 3.7

跑完 logs/myspeaker/ 下会多出 0_gt_wavs（目标采样率的切片）、1_16k_wavs（提特征用的 16k 副本）、2a_f0、2b-f0nsf。数量对不上就说明切片失败，先解决这个再往下走。

# 提 HuBERT 特征（v2 是 768 维，落在 3_feature768/）
python train/dataset/extract_hubert_feature.py \
  cpu 1 0 "`pwd`/logs/myspeaker" v2 False

注意事项：这一步会加载 assets/hubert_base，日志里出现 masked_spec_embed MISSING 是正常的，不代表加载失败。

第四步：配置文件（最容易卡住的地方）

训练脚本启动时会去读 logs/myspeaker/config.json，而这个文件不会在预处理时自动生成。图形界面会帮你写，命令行不会。仓库里 configs/v2/ 只有 32k 和 48k 的模板，40k 的模板缺失——我第一次跑 40k 就是这么崩的，日志里报：

json.decoder.JSONDecodeError: Extra data: line 1 column 4 (char 3)

打开 config.json 一看，里面只有一行 404: Not Found。两个办法：把 configs/v2/32k.json 复制过去改参数，或者直接写一份 40k 的：

{
  "train": { "log_interval": 200, "seed": 1234, "epochs": 20000,
             "learning_rate": 1e-4, "betas": [0.8, 0.99], "eps": 1e-9,
             "batch_size": 4, "lr_decay": 0.999875, "segment_size": 12800,
             "init_lr_ratio": 1, "warmup_epochs": 0, "c_mel": 45, "c_kl": 1.0 },
  "data": { "max_wav_value": 32768.0, "sampling_rate": 40000,
            "filter_length": 2048, "hop_length": 400, "win_length": 2048,
            "n_mel_channels": 125, "mel_fmin": 0.0, "mel_fmax": null },
  "model": { "inter_channels": 192, "hidden_channels": 192, "filter_channels": 768,
             "n_heads": 2, "n_layers": 6, "kernel_size": 3, "p_dropout": 0,
             "resblock": "1", "resblock_kernel_sizes": [3,7,11],
             "resblock_dilation_sizes": [[1,3,5],[1,3,5],[1,3,5]],
             "upsample_rates": [10,10,2,2], "upsample_initial_channel": 512,
             "upsample_kernel_sizes": [16,16,4,4],
             "use_spectral_norm": false, "gin_channels": 256, "spk_embed_dim": 109 }
}

32k 的模板要改三处：sampling_rate 32000、filter_length/hop_length/win_length 1024/320/1024、n_mel_channels 80。别只改采样率，mel 参数不一致会直接训崩。

还要一份 filelist.txt，每行是 切片路径|特征路径|f0 路径|f0nsf 路径|说话人 id。图形界面第三步会生成它；纯命令行的话，最省事的做法是用界面点一次「处理数据」，拿到 filelist 和 config 之后，再回到命令行训。

第五步：开训

# 40k、带 f0、200 轮、每 25 轮存一次权重
python -m train.train -e myspeaker -sr 40k -f0 1 -bs 4 -g 0 \
  -te 200 -se 25 \
  -pg assets/pretrained_v2/f0G40k.pth \
  -pd assets/pretrained_v2/f0D40k.pth \
  -l 0 -c 0 -sw 1 -v v2
参数含义建议
-e实验名对应 logs/<名字>
-sr采样率32k 快、40k 好听，先 32k 验证流程
-bs批大小8GB 内存用 4，够大就 6～8
-te / -se总轮数 / 存档间隔200 / 25，够听第一版
-sw是否导出小模型1 = 每 -se 轮存一个 assets/weights/*.pth

日志里每轮一行 ====> Epoch: N [时间] | (耗时)，40k 大约 1.5～1.7 分钟一轮，32k 快三倍左右。断点续训就把 assets/weights 里的模型当 -pg/-pd 传进去。

注意事项：200 轮只是「能听」，不是「好听」。判断标准不是轮数而是试听：每 25 轮存的那一版都拿去换一句固定的话，对比到「再训也没变化」就停。我这次的 200 轮 40k，音色能对上，但语气还是平——问题在语料，不在轮数。

第六步：建索引（可选，但强烈建议）

python train/train_index.py "myspeaker" v2 "`pwd`/assets/indices" 8 auto

索引让推理时能从训练集里检索相似片段，音色更贴、更稳。建完在 logs/myspeaker/ 下会有一个 added_IVF*.index，推理时用 --index-rate 控制它的影响强度。

第七步：换声

cd /path/to/Retrieval-based-Voice-Conversion-WebUI

KMP_DUPLICATE_LIB_OK=TRUE PYTHONPATH=. python infer/cli.py \
  --model assets/weights/myspeaker_e200_s1600.pth \
  --input vocal.wav --output vocal_rvc.wav \
  --pitch 0 --index-rate 0.75 --f0-method rmvpe \
  --format wav --overwrite
  • --pitch：跨性别换声的关键。女声模型唱男声原曲给 +5 左右，女转女给 0，别乱加。
  • --index-rate：0.6～0.75 比较稳，太高会把原唱的口音也拽过来。
  • --f0-method：rmvpe 准，pm 快；pm 跑出来会明显飘。

注意事项：输出固定是「模型采样率 + 单声道」。32k 模型出来就是 32k/单声道，混音前记得 ffmpeg -ar 48000 -ac 2 升上去，不然会和立体声伴奏对不上、并且听起来发闷。

第八步：混音（成品好不好听，八成在这）

换声出来的干声通常比伴奏小很多。这几条是实测下来能听的配比：

  • 增益：把人声 RMS 拉到伴奏 RMS 的 1.15 倍。我这次干声只有伴奏的 0.3，等于给了 3.7 倍增益，才不被淹。
  • 压伴奏：伴奏整体乘 0.85，再在人声活跃段做约 4dB 的侧链压低（200ms 包络 + 平滑）。
  • EQ：人声 highpass 110Hz、3kHz +3dB、9kHz +4dB、轻压缩；这一步能把「糊」救回来不少。
  • 响度：最后统一 loudnorm=I=-13:TP=-1.0。
ffmpeg -y -i mix.wav -af "loudnorm=I=-13:TP=-1.0" \
  -ar 48000 -b:a 320k out.mp3

注意事项：别用聊天软件的「语音条」发成品，会转成低码率 silk，几万块的设备也救不回来。发文件。

踩过的坑，一条条列出来

现象原因解法
OMP: Error #15 ... libomp.dylib already initialized多个 OpenMP 运行时被链进同一进程命令前加 KMP_DUPLICATE_LIB_OK=TRUE
No module named 'infer'从仓库根目录直接跑 infer/cli.py加 PYTHONPATH=.
JSONDecodeError: Extra dataconfig.json 里是一行 404: Not Found手写配置，见第四步
推理莫名其妙退出、无栈并发训练抢资源 / MPS 偶发停掉训练重跑；连续两次就换 CPU
换声出来很闷把 48k 立体声降成 44.1k 单声道再混全程 48k 立体声，最后再压
声音像机器人语料是 TTS 合成音换真人、带情绪的语料重新训，没有捷径

下次直接照着念的清单

  1. 拿 5～10 分钟干净、带情绪的单人干声，统一转 wav。
  2. train/preprocess.py 切片 → 检查 0_gt_wavs / 2a_f0 数量一致。
  3. extract_hubert_feature.py 提特征 → 确认 3_feature768 有文件。
  4. 写 config.json，生成 filelist.txt。
  5. train.train 先跑 32k 200 轮验证流程，再上 40k。
  6. train_index.py 建索引。
  7. infer/cli.py 换声，pitch 按性别差给，index-rate 0.7 左右。
  8. 升到 48k 立体声 → 人声 1.15×、伴奏 0.85 + 侧链 → loudnorm → 发文件。

整套跑下来，第一次大概要耗掉一个下午；第二次照着清单，两小时内能拿到成品。真正花时间的从来不是敲命令，而是找一段值得训的声音。
