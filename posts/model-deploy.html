在自己电脑上跑一个开源模型

从下载、量化、显存估算，到把它接进自己的前端。写给第一次动手的人，也写给我下一次忘了的时候。

2026-11-02约 12 分钟macOS / Linux / Windows 通用

先说清楚：什么时候该自己跑

三条判据，命中两条再动手：一是数据不能出本机，二是要反复压测同一个模型（换量化、换上下文、比延迟），三是断网也要能用。只是偶尔问几句话，用 API 更省事也更便宜——显卡和电费不便宜。

三件工具，先挑一件

工具适合代价
Ollama想十分钟内跑起来，接受它帮你决定参数底层是 llama.cpp，参数藏得深
llama.cpp要自己控 KV cache、批大小、量化文件命令行长，编译要过一遍
LM Studio图形界面、给人演示自动化和脚本不友好

下面的步骤以 Ollama 为主线，需要抠参数的地方会标出 llama.cpp 的等价做法。

第一步：先算显存，再挑模型

别先下模型，先算账。一条足够用的估算法则：

权重占用 ≈ 参数量 × 每参数字节数
   Q4_K_M ≈ 0.5 字节/参数      Q8_0 ≈ 1 字节/参数
KV cache ≈ 2 × 层数 × 头维度 × 上下文长度 × 批大小 × 2 字节(fp16)

例：7B 模型 Q4_K_M 约 4.4GB，32k 上下文再吃掉 2～3GB → 8GB 显存刚好，留 1GB 给系统

注意事项：显存爆掉最先表现为「模型加载成功但第一句话就没完没了地卡」，不是报错。看到输出变慢十倍，先砍上下文长度，再考虑换更小的量化。

第二步：装环境

# macOS / Linux
curl -fsSL https://ollama.com/install.sh | sh

# 只想用 Homebrew 装
brew install ollama && brew services start ollama

# Windows 直接用安装包，装完 ollama serve 已在后台跑

Apple Silicon 走 Metal，默认就启用；N 卡机器确认驱动版本够新，CUDA 跑在 12.x 上最稳。

第三步：拉模型、跑第一句

  1. 拉一个够小的模型试水 
    ollama pull qwen2.5:7b-instruct-q4_K_M
ollama run qwen2.5:7b-instruct-q4_K_M "用一句话解释什么是 KV cache"
  2. 限定上下文，别让它自动吃满 
    ollama run qwen2.5:7b-instruct-q4_K_M --context-length 8192
    等价地在 llama.cpp 里是 -c 8192。上下文是显存的第一号杀手。
  3. 确认它开的是 OpenAI 兼容端点 
    curl http://127.0.0.1:11434/v1/models
    能返回 JSON 列表就通了，后面接前端靠的就是这个 /v1。

第四步：接进前端

浏览器直连 http://127.0.0.1:11434/v1 会撞 CORS，也等于把本机端口暴露给任意页面。正确做法是让前端打到自己的代理，由服务端转发：

// app/api/chat/route.ts（Next.js，nodejs runtime）
export async function POST(req: Request) {
  const body = await req.json();
  const r = await fetch("http://127.0.0.1:11434/v1/chat/completions", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ ...body, stream: true }),
  });
  return new Response(r.body, { headers: { "Content-Type": "text/event-stream" } });
}

注意事项：把 stream: true 原样转发，别自己拼字符串——SSE 的 data: 前缀丢一个字节，前端就会一直转圈。

我踩过的坑

  • 模型下到一半断了：Ollama 会重试但不续传，换镜像或挂代理更省事；~/.ollama/models 里能看到半截文件，删掉重拉。
  • 端口被占：本机已有服务在 3000/11434 时，ollama serve 会静默换端口，先 lsof -i :11434 看一眼。
  • Mac 上内存交换：显存不够时系统会拿内存顶，风扇狂转、响应变慢，vm_stat 里的 swap 一直在涨就是信号。
  • 并发不是免费的：Ollama 默认串行处理请求，第二个请求排队；要并发得开 OLLAMA_NUM_PARALLEL，同时把 KV cache 的显存预算翻倍。
  • 别把 OLLAMA_HOST=0.0.0.0 开在咖啡厅 Wi-Fi 上：那等于把模型免费给整个局域网用。

接下来可以做的

跑通之后，值得花时间的顺序是：换成自己的提示词测稳定性 → 用同一批问题对比 Q4 和 Q8 的差别 → 再决定要不要上更大的模型。先加硬件往往是最贵的那条路。
